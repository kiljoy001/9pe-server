# 9P.e Server

A modern implementation of the 9P.e protocol with mesh networking, web UI, and cross-machine filesystem access.

## Features

- **9P.e Protocol**: Modern extension of Plan 9's 9P protocol
- **Security**: Ed25519 signatures, capability tokens, ACLs, rate limiting
- **Auto-Mount**: Automatic FUSE mounting for Linux clients
- **Mesh Networking**: Automatic peer discovery using libp2p gossipsub
- **Web Dashboard**: Real-time monitoring and file browsing
- **Cross-Platform**: Works on Linux, macOS, and Windows
- **Synthetic Files**: Dynamic content generation
- **Metrics**: Prometheus-compatible metrics export

## Quick Start

```bash
# Build the server
cargo build --release

# Serve current directory (local access only)
./target/release/9pe-server serve

# Serve with network access and auto-mount discovery
./target/release/9pe-server serve --bind 0.0.0.0:5641 --mesh-port 9650 --auto-mount

# Serve with web UI, mesh networking, and auto-mount
./target/release/9pe-server serve --bind 0.0.0.0:5641 --mesh-port 9650 --web-ui-port 8080 --auto-mount

# Auto-discover and mount all accessible servers (Linux clients)
./target/release/9pe-server auto-mount

# List discovered servers
./target/release/9pe-server peers
```

## Usage

### Serve Command

```bash
./target/release/9pe-server serve [OPTIONS]

OPTIONS:
    -p, --path <PATH>              Directory to serve [default: .]
    -b, --bind <BIND>              Address to bind to [default: 0.0.0.0:564]
    -e, --mesh-port <PORT>         Enable mesh networking on port
    -q, --quic                     Use QUIC transport (experimental)
    -n, --server-name <NAME>       Server name for QUIC TLS
    -m, --metrics-port <PORT>      Metrics port [default: 9090]
    -w, --web-ui-port <PORT>       Web UI port (optional)
    --mesh-node-id <ID>            Custom mesh node ID (auto-generated by default)
    --auto-mount                   Enable auto-mounting of discovered servers
```

### Accessing Remote Files

There are three ways to access files on remote 9P.e servers:

#### Method 1: Direct Connection
```bash
# List files on remote server
./target/release/9pe-server list --server 192.168.1.114:5641 --path /

# Copy a file from remote server
./target/release/9pe-server get --server 192.168.1.114:5641 --remote /path/to/file --local ./file

# Mount remote filesystem (Linux/macOS)
./target/release/9pe-server mount --server 192.168.1.114:5641 --mount-point /mnt/remote
# Now access files normally: ls /mnt/remote, cp /mnt/remote/file.txt .
```

#### Method 2: Web UI
```bash
# Start server with web UI
./9pe-server serve --bind 0.0.0.0:5641 --mesh-port 9650 --web-ui-port 8080

# Access in browser
http://192.168.1.114:8080

# Browse remote files, download, upload through web interface
```

#### Method 3: Automatic Mesh Discovery
```bash
# Both machines run with mesh enabled
./9pe-server serve --bind 0.0.0.0:5641 --mesh-port 9650

# Discover all peers on network
./9pe-server discover

# List discovered peers and auto-connect
./9pe-server peers
# Shows: 192.168.1.114:5641 (peer-id: 12D3KooW...)

# Access discovered peer's files
./9pe-server auto-list --path /
```

#### Method 4: Automatic FUSE Mounting (Linux)
```bash
# Auto-discover and mount all accessible servers
./9pe-server auto-mount

# List active mounts
./9pe-server mounts

# Manual mount of specific server
./9pe-server mount --server 192.168.1.114:5641 --mount-point /mnt/remote

# Access files like local filesystem
ls /tmp/9pe-mounts/node-192_168_1_114/
cp /tmp/9pe-mounts/node-192_168_1_114/file.txt .
```

### Network Access Configuration

**Important**: For network access between machines:

1. **Bind to all interfaces**: Use `--bind 0.0.0.0:5641` not `127.0.0.1:5641`
2. **Enable mesh networking**: Add `--mesh-port 9650` for automatic peer discovery
3. **Check firewall**: Ensure ports are open (5641 for 9P.e, 9650 for mesh)

#### Example: Setting up a network-accessible server

```bash
# On server machine (e.g., 192.168.1.114)
./9pe-server serve --path /home/user --bind 0.0.0.0:5641 --mesh-port 9650

# On client machine (e.g., 192.168.1.182)
./9pe-server list --server 192.168.1.114:5641 --path /
```

### Mesh Networking

The mesh networking feature uses libp2p gossipsub protocol for automatic peer discovery:

```bash
# Start server with mesh networking
./9pe-server serve --mesh-port 9650 --bind 0.0.0.0:5641

# Peers will automatically discover each other via:
# - mDNS for local network discovery
# - Kademlia DHT for distributed routing
# - Gossipsub for message propagation
```

When mesh is enabled, you'll see:
- `🔍 Discovered peer via mDNS`: Automatic peer discovery
- `🤝 Connected to peer`: Successful peer connection
- `🆔 Identified peer`: Peer protocol identification

## Architecture

The server implements:

- **Core Protocol**: 9P.e message handling
- **Mesh Networking**: libp2p-based peer discovery and communication
- **Web UI**: HTTP server for dashboard and file browsing
- **Synthetic Files**: Dynamic content generation for special paths
- **Metrics**: Prometheus-compatible metrics collection

### Mesh Network Topics

- `9pe-discovery`: Node announcements and capabilities
- `9pe-consensus`: GhostDAG consensus messages
- `9pe-file-sync`: File synchronization requests/responses

## Synthetic Files

The server provides synthetic files that generate content dynamically:

- `/sys/cpuinfo` - CPU information
- `/sys/meminfo` - Memory statistics
- `/sys/netstat` - Network connections
- `/sys/timestamp` - Current timestamp
- `/sys/metrics` - Prometheus metrics
- `/dev/random` - Random data stream
- `/dev/zero` - Zero byte stream
- `/proc/list` - Process list
- `/ui/dashboard.html` - Web dashboard
- `/draw/main/canvas.html` - Graphics canvas

## Security Features

### Authentication & Authorization
- **Ed25519 Digital Signatures**: Cryptographically secure authentication
- **Capability Tokens**: Time-limited, revocable access tokens
- **Access Control Lists**: Fine-grained path-based permissions
- **Rate Limiting**: DoS protection with configurable limits

### FUSE Mount Security
- **Auto-mounting** only for servers that grant access
- **Read-only** mounts by default for safety
- **Permission validation** before mounting
- **Secure unmounting** with cleanup

### Network Security
- Always use `--bind 0.0.0.0:PORT` for network access
- Consider firewall rules for production deployment
- QUIC transport provides built-in encryption (experimental)
- Mesh networking uses authenticated libp2p connections

### Usage Example with Security
```bash
# Server with security enabled
./9pe-server serve --bind 0.0.0.0:5641 --mesh-port 9650 --auto-mount

# Client auto-discovery with authentication
./9pe-server auto-mount
# Only mounts servers that grant access to this user
```
